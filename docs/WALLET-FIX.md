# Direct wallet connection

The public app connects directly to a wallet supplied by the browser, using EIP-1193 and EIP-6963 provider discovery. No project ID, relay, QR pairing service or external wallet SDK is required. The wallet still has to be available in the browser and the user must approve account access and any network change. An ordinary browser without an installed/injected wallet cannot connect to a separate phone wallet by itself.

The app requests eth_requestAccounts, reads eth_chainId, asks the wallet to switch to Robinhood Chain 4663 (0x1237), and offers official network metadata if the wallet returns unknown-chain error 4902. It then re-reads eth_accounts and eth_chainId before showing a connected address. Rejections, pending requests and unsupported switching produce useful errors. Account, network and disconnect events clear verified connection state. No token approval, transfer, transaction signing or message signing is implemented. No mainnet contract deployment is performed.

Provider discovery supports announced browser wallets and legacy window.ethereum. When several wallets are available the user chooses; none is impersonated. Open the site in a compatible wallet Web3 browser or in a browser with an Ethereum wallet installed. Robinhood's official connection guide documents its Web3 browser on iOS: https://robinhood.com/us/en/support/articles/connect-to-dapps/

The latest owner-supplied PNG is used unchanged as the logo, without cropping. Partnership wording remains. All transaction actions remain unavailable.
Validation: 14 automated checks passed, covering provider discovery, canonical mainnet configuration, network switching/addition, rejection, revoked access, wrong network, account/network changes, missing-wallet UI and production output. Browser inspection confirmed an immediate missing-wallet state with no relay wait or console error. Real wallet approval must be completed by the wallet owner; no external wallet was available in the automated browser.
